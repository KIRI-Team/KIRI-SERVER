# KIRI 관리자 API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계 문서의 관리자 API 1차(인증·감사 로그, 조회, 수집 관리, 검수 2탭, 수동 콘텐츠, 끼리 픽, 이벤트 수집, KPI)를 KIRI-SERVER에 구현한다.

**Architecture:** `/api/admin/**` 전용 `SecurityFilterChain`(Order 1)과 `admin_access` 타입 JWT로 앱 인증과 분리한다. 관리자 코드는 `com.kiri.server.admin.*` 하위 기능 패키지에 두고 기존 도메인 엔티티·리포지토리를 재사용하며, 상태 변경은 엔티티 도메인 메서드로 한다. 모든 변경 API는 같은 트랜잭션에서 `admin_audit_log`를 남긴다.

**Tech Stack:** Spring Boot 4.1, Java 25, JPA/Hibernate, PostgreSQL 18, Flyway, jjwt 0.13, springdoc 3, JUnit5 + MockMvc + 실 Postgres(`@SpringBootTest @Transactional`).

**Spec:** `docs/superpowers/specs/2026-11-10-admin-api-design.md`

## Global Constraints

- 스키마 변경은 Flyway `V28__`부터 순서대로. `ddl-auto: validate`가 통과해야 한다.
- 응답은 `ApiResponse.onSuccess(code, result)`, 에러는 `ProjectException` + 도메인별 `*ErrorCode`(`ADMIN400_1` 형식).
- 관리자 권한은 `ROLE_ADMIN` 하나. 로그인은 `loginId` + `password`(BCrypt). 최초 계정 자동 생성·로그인 잠금 없음.
- 관리자 토큰 type 클레임: `admin_access`(1시간), `admin_refresh`(7일). 앱 토큰(`access`)과 상호 불통.
- 집계는 Asia/Seoul, 주는 월요일 00:00 시작. `member.is_test` / `family.is_test` = true는 KPI에서 제외.
- 사유 필수 액션: 검수 보류·제외, 공개 대기 숨김, 미션 숨김·복구, 공개 중 미션 수정, 민감정보 열람, 수집 중단.
- 컨트롤러는 기존처럼 `*ControllerDocs` 인터페이스로 Swagger 문서를 분리하고, springdoc `GroupedOpenApi` `admin` 그룹을 둔다.

## Review Focus

1. 앱 JWT로 `/api/admin/**` 호출 / 관리자 JWT로 `/api/v1/**` 호출 → 둘 다 401. (Task 1 테스트)
2. 비활성화된 관리자의 기존 토큰 → 401. (Task 1 테스트)
3. 끼리 픽 상단 정렬 시 커서 페이지에서 중복·누락 없음, 필터 불일치 픽 미노출. (Task 6 테스트)
4. 검수 승인 시 `ENDED`/`CANCELLED`/`HIDDEN` 미션 상태 유지, 제외 레코드는 원본이 바뀌어도 `IGNORED` 유지. (Task 4 테스트)
5. 잠금 필드가 재수집(`updateContent`)에서 보존. (Task 4 테스트)

### Task 3: 수집 관리 (V30)

- V30: `external_sync_state.admin_paused` BOOLEAN NOT NULL DEFAULT FALSE.
- `TourApiSyncScheduler.sync/fullCheck`와 수동 실행이 `admin_paused`면 건너뜀(`TourApiSyncService` 진입부 체크).

- 테스트: 일시정지 시 sync 건너뜀, 실행 중 409, 미지원 출처 400, retry 리셋.

### Task 4: 미션 검수 2탭 + 잠금 필드 (V31)

- V31: `external_record.review_requested_at`(백필), `mission_review_task`(+부분 unique open), `mission.locked_fields TEXT[]`(title_edited/checklist_edited 백필), `place.locked_fields TEXT[]`, `mission.origin`(EXTERNAL 백필), `mission.reservation_url`.
- 엔티티: `MissionStatus.DRAFT`, `ReviewReason.ADMIN_EXCLUDED`, `MissionOrigin`, `LockedField` enum, `Mission.updateContent`가 잠금 필드 보존, `Place.refreshImage`가 IMAGE 잠금 보존, `ExternalRecord.markReviewRequired`가 시각 기록.
- `admin/review` 탭①: 목록/상세/담당자/재검증/승인/보류/제외. 탭②: `pending-publish` 목록/publish/hide/bulk.
- 재검증·승인은 원본으로 만든 `MissionDraft`에 보완 값(`ReviewOverrides`)을 덮어 `MissionDraftValidator`로 검사.
- 테스트: 승인 시 상태 규칙(CHECK_REQUIRED→ACTIVE, 기간 지남→ENDED, ENDED/CANCELLED/HIDDEN 유지), 제외 후 재수집 IGNORED 유지, 탭② publish/hide, 숨김 미션 재수집 유지, 잠금 필드 보존, 이전 승인 표시.
